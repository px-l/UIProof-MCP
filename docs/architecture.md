# 技术设计

## 边界与数据流

UIProof 使用 TypeScript、Playwright、pixelmatch、sharp 和官方 MCP TypeScript SDK。CLI 与 MCP 调用同一业务函数，报告生成不依赖外部 CDN 或模型。

1. `config.ts` 验证配置和文件路径。真实路径必须在工作目录内，防止 `../` 和越界符号链接读取。
2. `capture.ts` 为每个状态创建独立 Chromium 上下文，执行有限动作、等待就绪、确认连续稳定帧，收集视口截图及可见元素边界。
3. `compare.ts` 将设计和页面转换为 sRGB RGBA，严格校验尺寸，按显式偏移对齐。pixelmatch 输出透明差异蒙版；16px 网格连通区域聚合差异，抗锯齿和蒙版可配置。
4. `runner.ts` 保存基准快照、采集环境、图片哈希、截图、差异图、带框标注和局部证据。最多 99 个独立区域加一个剩余区域集合，所有不同像素都保留。
5. `report.ts` 生成静态 HTML。所有非固定文案转义，CSP 禁止脚本及外部资源。JSON 与 HTML 使用临时文件替换，避免客户端读到写入一半的文件。
6. `server.ts` 暴露 stdio MCP 工具和修复 Prompt。耗时任务返回 job ID，同一进程串行执行；只读取配置与证据，不执行 shell。
7. `analysis.ts` 为已完成的比较发送图片到显式启用的多模态端点；校验结构、类别、置信度和坐标，独立存储，不改像素结果。
8. `figma.ts` 锁定版本下载节点和 PNG，记录节点相对坐标，并校验元数据与基准哈希对应关系。
9. `tracking.ts` 在复验差异图中检查原区域剩余像素，报告空间意义上的消失/剩余/新增，不能推断业务功能是否正确。

## 产物

```text
.uiproof/<run-id>/
├── run.json
├── index.html
└── <state>/
    ├── baseline.source       # 原始设计字节
    ├── design.source.json    # 可选 Figma 元数据快照
    ├── raw.png               # 未对齐的页面截图
    ├── expected.png
    ├── actual.png            # 显式对齐后的页面图
    ├── diff.png              # 透明差异蒙版
    ├── annotated.png         # 编号红框
    └── issue-001-{expected,actual,diff}.png
```

每次复验创建新的运行目录。没有覆盖原基准的 API。哈希用于检测意外修改，不是防范有权修改整个工作目录的攻击者的数字签名。

## 稳定性与限制

截图是有限时间的观察，不能证明页面之后不会变化；业务必须提供稳定测试数据和可靠就绪信号。相同设计不代表相同字体渲染环境，正式回归应固定系统、浏览器版本和字体。像素结果适合几何/颜色差异，语义缺失通过局部图、Figma 元数据和模型辅助解释；两者不能替代功能测试。

当前对齐仅支持显式整数平移。默认严格 1:1 像素对应，尺寸不一致直接 `error`。不会通过缩放和裁边隐藏布局缺陷。

## 信任边界

工作目录、配置和操作步骤应由操作者审阅；页面 URL 可以访问本机及私有服务，所以不要将该 stdio 服务直接包装成公开无鉴权网络接口。click/fill 可能触发目标页面的业务动作，请使用测试环境和测试数据。

截图、DOM、Figma 节点和模型输出都可能包含敏感数据或提示注入。服务不会执行这些文本中的指令；客户端仍应将其视作证据数据。运行目录不应上传到公开仓库；蒙版不脱敏。远程分析要求环境变量显式开启，密钥只从环境读取，网络请求有限时/限大小、不自动跟随重定向。

当前任务队列在进程内；服务重启后可以列举完整运行，但不恢复未完成任务。多进程同时分析同一 run 的结果采用最后完成者覆盖，应避免并发操纵同一工作目录。
